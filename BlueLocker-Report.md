Blue Locker Ransomware Detection Report1. Threat Profile: Blue Locker RansomwareAttack Nature: This simulation focuses on a high-speed encryption event where the adversary attempts to lock user files using the .blue extension.  Impact: Rapid loss of data availability across the target workstation.  Objective: Move beyond static signature detection to identify the behavioral pattern of mass file encryption.  2. Detection Strategy: Frequency-Based CorrelationTelemetry Source: We utilize Windows Sysmon Event ID 11 (FileCreate) to monitor file system activity in real-time.  Logic: A single file creation is normal; however, ransomware requires a massive number of file modifications in a very short window to be effective.  The "50/2" Rule: I configured a frequency-based correlation rule that triggers only when 50 file creation events occur within a 2-second window.  3. Severity & ResponseAlert Level: Assigned Level 12 (Fatal Alert) to ensure this event bypasses lower-priority noise and immediately alerts the SOC Analyst.  Mitigation: This high-severity alert is designed to trigger automated containment protocols to isolate the host before encryption completes.4. Technical Logic (Wazuh XML)This logic is deployed in the rulesets/local_rules.xml file of this repository:XML<rule id="100004" level="12">
  <if_sid>60103</if_sid> <field name="win.eventdata.targetFilename">\.blue$</field>
  <description>Massive File Creation Detected: Possible Ransomware Activity (.blue extension)</description>
  <frequency>50</frequency>
  <timeframe>2</timeframe>
  <group>pci_dss_10.6.1,gdpr_IV_35.7.d,blue_team_simulation</group>
</rule>
5. Evidence & ValidationValidation: This rule was validated by ingesting raw logs from a simulated "Blue Locker" execution, successfully isolating the millisecond gaps between file creations.
